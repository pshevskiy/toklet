# Bounded Llama default Mac adoption

The default Mac Models catalog now includes the pinned Llama3.2 1B eight-bit
artifact. Search, recommendations and saved-model lookup use that same catalog.
The row states “Mac chat window: 512 tokens.” The audited managed loader, strict
model/tokenizer identity, numerical/text/process budgets and512-position limit
are unchanged. Ordinary folder opening directs users to Models before altering
an accepted owner or conversation. iOS retains its four-profile catalog pending
physical iPhone14Pro qualification.

Adoption follows the [original loss/task qualification](llama3-quality-qualification.md)
and [fresh ranged-download/offline journey](llama3-download-offline.md). It covers
this artifact and bounded Mac Chat, not every Llama export or the declared
131,072-position window. It adds no performance claim.

Focused controls pass default Mac catalog/name/search, audited identity,
context/KV/preferences, ranking and discovery. Llama requires its3GiB process
allowance; one byte below is rejected. Mac discovery has six bounded20-row
requests; iOS retains five. The recommendation list remains bounded to five.
Strict Mac, iOS and simulator app checks pass. The first focused compile rejected
an unreachable test branch after the old runtime flag became platform support;
explicit platform expectations corrected it, and the failed log remains.

A real unflagged cached controller passes open, send, Stop, recovery and reopen,
including ordinary-folder rejection preserving state and preference isolation.
An isolated production-view fixture launches without a flag. Its Models sheet
shows the default Llama row and512-position notice; Use model opens it, the
header reports Llama on device and selected512, and Send displays “Hello.” The
fixture is closed afterward. Its cache links are read-only test inputs; corruption
checks used private copies in the separate transfer journey. Monitor values are
UI observations, not benchmark samples. A transient UI transport error during
Use was followed by observed loading and successful completion.

The historical opt-in route remains recorded; its old flag is unnecessary.
The native40 package is unchanged. Physical iPhone support, larger contexts and
other model configurations remain separate qualifications.
