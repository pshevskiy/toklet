# Additional Hugging Face Chat model

Toklet adds `mlx-community/Qwen3-0.6B-8bit` at immutable revision
`11de96878523501bcaa86104e3c186de07ff9068` to its downloadable Chat catalog.
Its six pinned files total 644,927,148 bytes. This is the fourth supported
catalog profile, not a claim that all four fit an iPhone. Find best model now
queries five bounded public Hugging Face metadata pages. Other discoveries stay
browseable; ranking never grants graph, format, tokenizer or memory eligibility.

The profile uses the [qualified Qwen3 native Chat route](qwen3-native-chat.md),
including its independently frozen non-thinking template, EOS 151645 and
original added-token decode flags. Numerical, text and process reservations are
1,536/256/2,304 MiB. Actual load planning and fresh admission after releasing the
previous model remain mandatory. Unsupported quantizations and other repository
revisions are not aliases for this profile.

The installed native package is built from commit
`40bf67fc1dca5fff2e4bc65fed0c42dead959f80`; its build receipt SHA256 is
`23a4dc81423522f8a4655c623f4e0f0642997d581f16e14b1fbb3c69277a02b8`.
Later parallel Rust changes are outside this immutable package. The
[phone receipt](../benchmarks/results/2026-10-25-mobile-qwen3-phone-v1.json)
binds the source, package, signed files and retained raw evidence.

On 25 October 2026, all seven XCUITest cases passed on iPhone 14 Pro / iOS
27.0.1, with zero failures and skips. These cover live discovery and ranking,
dashboard/dialog controls, repeated SmolLM2/Qwen2/Qwen3 switching, actual Qwen3
Chat replies after backgrounding and re-selection, colored Python output with
successful Copy feedback, and the existing Expert numeric-fixture highlighting.
The Expert fixture is a rendering/control witness, not a Qwen3 raw-generation
quality test. Tests used isolated histories; owner saved-chat bytes matched
before and after, and the updated app was normally launched afterward.

A separate fresh transfer used an exclusive temporary directory and reported
`reusedSnapshot=false`, the exact pinned revision and 644,927,148 bytes. Native
generation produced three eight-token replies whose IDs matched the Mac run.
Context rejection preserved the prefix; cancellation, explicit resume and handle
release passed. The downloaded model also generated through the actual offline
controller with every network callback configured to throw. Both installed-file
proofs matched the seven signed host files.

The fresh process's observed lifetime physical-footprint peak was 893,274,528
bytes (851.9 MiB), below its 2,304 MiB process reservation. Snapshots cover load,
generation and release in native and offline-controller paths. This is a
cumulative process high-water mark, not a per-stage allocation delta. Handle
release does not claim that allocator/driver caches return to the startup
footprint. The dashboard also displayed actual RAM, TTFT and decode rate.

These short UI observations are not a controlled speed comparison or quality
score. Local checks passed ten owned commands plus eight interface checks,
including four real profiles, transport cleanup, offline controller generation
and SmolLM2 → Qwen3 → SmolLM2 admission. The signed iOS build and strict app/runner
signature checks passed. Four earlier physical attempts remain unaccepted and
retained: their new test locators failed while all six pre-existing cases passed;
each restored the previous verified app with matching owner bytes. The final
runner uses actual viewport bounds and small bidirectional gutter gestures so
nested horizontal code scrolling and gesture overshoot cannot qualify Copy.

Chat output remains 256 tokens, raw Expert output 128, and Chat context 512
positions. This addition does not qualify Gemma 4 or a 131,072-token reply.
Those remain prioritized in the [Gemma implementation plan](gemma4-implementation-plan.md)
and [long-reply plan](long-reply-engine-plan.md). They require a real runnable
checkpoint, explicit capabilities, an immutable iOS package and independent phone
admission; a tiny graph or a 131,072-ID text decoder does not establish them.
