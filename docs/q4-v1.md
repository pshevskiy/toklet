# Toklet Q4 version 1

This is Toklet's engine format, with no MLX/container compatibility claim.
M5.1 freezes a matrix artifact and CPU reconstruction oracle; model admission,
GPU execution and held-out quality are separate tasks.

Eligible model tensors are the seven layer matrices Q, K, V, O, gate, up and
down. Norm vectors, Q/K/V biases and the tied embedding/output matrix remain
FP16. The tied matrix is stored once. A model manifest must bind the original
checkpoint/config hashes, this quantizer identity, each matrix shape and each
packed artifact hash. Matrix files alone do not identify a model.

All integer and floating-point bytes are little endian. Rows follow linear
`[out_features, in_features]` order. Each row has independent groups of 64
consecutive input features, including a final partial group. No transpose or
cross-row group is permitted.

| Header offset | Size | Meaning |
| --- | --- | --- |
| 0 | 8 | `TOKQ4V1` followed by zero byte |
| 8 | 4 | Unsigned version, exactly 1 |
| 12 | 4 | Unsigned group size, exactly 64 |
| 16 | 8 | Positive unsigned row count |
| 24 | 8 | Positive unsigned column count |
| 32 | 8 | Row stride in bytes |
| 40 | 8 | Payload byte count |
| 48 | 16 | Zero reserved bytes |

The payload immediately follows this 64-byte header. Each group record is 36
bytes: FP16 scale (2), FP16 bias (2), then 32 code bytes. The earlier column uses
the low nibble; the next column uses the high nibble. Group records are contiguous
within a row. Row stride is `ceil(36 * ceil(columns / 64) / 64) * 64`; row starts
are file-relative 64-byte aligned, metadata is 4-byte aligned. No actual pointer
alignment is implied by Rust byte slices. Unused tail codes and row padding are
zero. There is no trailing data. The parser rejects noncanonical padding,
negative scale (including negative zero), nonfinite metadata, incompatible
version, arithmetic overflow and inconsistent lengths before exposing weights.

The quantizer identity is `toklet-q4-affine-f32-source-half-metadata-rne-v1`.
Source values are decoded to FP32 first (BF16/FP16 sources convert exactly),
without first rounding the whole source to FP16. Reject nonfinite source values.
Extrema use only valid values in each group. Calculate `bias = minimum` and
`scale = (maximum - minimum) / 15` in FP64, then round both to FP16 using IEEE
round-to-nearest, ties-to-even. Reject metadata overflow; normalize zero metadata
to positive zero. For nonconstant groups whose scale rounds to zero, use the
smallest positive FP16 subnormal, `2^-24`. Do not flush subnormals.

Choose each code using the **rounded** metadata:
`clip(round_ties_to_even((source - bias) / scale), 0, 15)` in FP64.
For an exactly constant group, scale is zero and every code is zero; reconstruction
is the rounded bias. Row padding does not influence extrema or code selection.
This format does not optimize scales or use calibration data.

Reconstruct `FP32(scale) * FP32(code) + FP32(bias)` with FP32 storage, without
an additional Half cast. The product is exactly representable; the addition may
round. This can exceed finite Half range even for source values within that
range, so later GPU conversion must check its own numerical boundary. The Rust
matvec oracle multiplies these reconstructed FP32 values by FP32 inputs and sums
in FP64, with a checked FP32 result. Its doubled scalar traversal prevents partial
output on overflow and is a diagnostic reference, not a hot-path optimization.

The standard-library [packer](../tools/quantization/q4.py) streams one FP32 row
at a time, refuses existing outputs, limits artifact size to 6 GiB and raw row
conversion to 16 MiB, and deletes its own incomplete output on failure. Its JSON
result binds the exact source byte stream, quantizer, dimensions and packed bytes:

```sh
python3 tools/quantization/q4.py weights.f32le weights.q4 --rows 896 --columns 896
```

The standalone row conversion limit covers raw input, not Python object overhead
or an entire model working set. The model packer/loader must account for those
resources separately. Existing FP16/FP32 artifacts and quality gates are unchanged.

## Source-bound model artifact

[model.py](../tools/quantization/model.py) exports exactly the seven eligible
matrices per layer from local F32/F16/BF16 safetensors, including indexed shards:

```sh
python3 tools/quantization/model.py models/Qwen2.5-0.5B-Instruct artifacts/qwen-q4
```

It creates a fresh directory with `<source_tensor_name>.q4` matrix files and a
final `manifest.json`. No exclusions are duplicated: the runtime still loads
them from the original checkpoint. The manifest has format `toklet-q4-model-v1`,
the quantizer identity above, `config_sha256`, a `sources` array of plain local
`file`/`sha256` entries for every shard and optional index, and a `matrices` array.
Each matrix entry records `name`, `file`, `rows`, `columns`, `packed_bytes`,
`packed_sha256`, and `source_f32_sha256` (decoded row-major FP32LE values).
`packed_matrix_bytes` is the sum of matrix files including headers/padding.
`exclusions` is exactly `norms`, `qkv_biases`, `tied_embedding_output` in that order;
`excluded_dtype` is `F16`. There are no unspecified manifest fields.

Config/index identities hash the exact bounded bytes parsed. Shard identities
are established before header interpretation. Final hashes check all source
endpoints before publishing a manifest. Source JSON is limited to 1 MiB, aggregate
safetensors headers to 16 MiB, shards to 1,024, and layers to 1,024. Each matrix
streams one row through the unchanged v1 quantizer. Hashes use 64 KiB reads.
An unsuccessful run retains complete matrices for diagnosis but publishes no
usable manifest; a failing current matrix/manifest is deleted, including final
flush errors. An existing directory is preserved.

The Rust `Artifact` API receives an independently validated expected matrix
shape map and source-file inventory from its caller. It validates exact inventories,
hashes, exclusions, lengths, version policy and a bounded manifest before admitting
`packed_matrix_bytes + largest_matrix_bytes + 64 MiB + 64 KiB`. The largest matrix
allows one staging allocation while packed GPU buffers are resident. The runtime
must additionally admit actual FP16 exclusions, KV, scratch and application state.
Each staging read rehashes the exact returned bytes and validates the full matrix
header/metadata/padding; hashes alone do not bypass structural validation.
Source hashes can be checked again after excluded-weight loading. The decoded
source hash is quantizer provenance; the Rust loader does not rerun quantization
of the entire source checkpoint to authenticate that field.
