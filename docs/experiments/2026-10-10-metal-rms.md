# FP16 Metal RMS normalization, 10 October 2026

The standalone [Rust RMS primitive](../../tools/experiments/rust_metal_rms.rs)
and [shader](../../tools/experiments/rust_metal_rms.metal) implement one
normalization operation with FP16 input/weight/output storage and FP32 arithmetic.
Native qualification passes on Apple M1 Pro. Its frozen gates come from the existing
[independent FP16 fixture](../../tests/fixtures/fp16-v1/manifest.json), anchored to
the original [FP32 source](../../tests/fixtures/tiny-v1/manifest.json); no numerical
gate or expected array changes.

## Arithmetic and layout

Input and output are contiguous `[rows, hidden]`; norm weights are `[hidden]`.
The initial kernel assigns one complete row to each thread. It sums squared
promoted Half values in increasing feature order as FP32, computes
`1 / sqrt(mean_square + epsilon)`, then multiplies each promoted input by that
inverse and its promoted weight before one final Half store. Floating-point
contraction is disabled explicitly; compile options require Metal 2.3, safe
math and precise functions and are read back before compilation.

This serial reduction is a small correctness reference. It rereads each input
row for scaling and traverses features contiguously within a thread; adjacent
threads own separate rows. It does not tune coalescing or parallel reduction.
For width 32, the logical traffic is 256 bytes per row before cache effects:
two reads of each input Half, one weight Half read and one output Half write.
Weight data can be reused across rows. No latency acceptance follows.

Three resident shared buffers hold input, weights and output, each with seven
Half-bit sentinels after its logical data. The private generic owner has exactly
two scalar uses: the previous FP32 add check and stored Half bits as `u16`.
Both types admit all Rust bit representations and zero initialization. Actual
length, storage/hazard mode and required scalar alignment are checked; no
stronger vector alignment is assumed. No owner, handle or borrowed slice escapes.

The shader receives input/weight/output at slots 0/1/2 with offset zero.
Slot 3 copies three UInt32 values: rows, hidden and exact FP32 epsilon bits.
Rust `repr(C)` size/alignment are asserted as 12/4 bytes; Metal uses the matching
three-field structure. Checked inventory bounds ensure all shape products and
rounded row indices fit shader UInt32 indexing. Tail rows return before access.

The pipeline/queue are cached once per process. Buffers persist across three
warmups and ten samples per case. Input/weight upload finishes before the first
submission, and output guards are reset before each submission. One retained
command is encoded and waited to completion; status/error checks precede every
diagnostic read. Every repetition compares input and weight bits, including
their guards, checks all output guards and rejects nonfinite Half output.
Autorelease pools bound temporary native resources. Failed commands are waited
before owners are released; the operation has no model/session state to commit.

## Independent gates and bounded evidence

The [Python driver](../../tools/experiments/rust_metal_rms.py) selects five
normalization stages from each of the five frozen tiny cases: both input norms,
both post-attention norms and final norm. Inputs use the appropriate independent
FP16 embeddings, residuals or preceding layer outputs; norm weights use the
frozen FP16 weight arrays. All 25 outputs, 7,040 values per full inventory, are
compared with the original FP32 source under their unchanged pre-GPU gates.
Exact agreement with the independent FP16 bits is an additional diagnostic,
not an acceptance rule substituted for the original source gate.
Both manifest identities are pinned in the driver. It hashes and parses the
same bounded bytes, checks every selected payload hash and rechecks manifests
after execution, so altered gates cannot silently qualify.

Three additional manual constant rows use zero, maximum finite Half and minimum
Half subnormal inputs with unit weights. Their hardcoded exact Half outputs are
zero, one and subnormal bit pattern 1,000. An independent FP64 constant-row
formula with the exact FP32 epsilon verifies those bits before GPU execution.
These cases detect missing epsilon, Half accumulation overflow and flushed small
inputs. They also use the original RMS tolerance for FP32-reference diagnostics;
exact manual Half bits are required. Total inventory is 28 cases and 7,136 values.

The artifact loader bounds files to one MiB, 1–32 unique bounded identifiers,
1–32 rows, widths 32/896 and at most 8,192 total output elements. It rejects
invalid lengths, nonfinite Half inputs/weights and nonpositive/nonfinite epsilon
before creating a device. Width 896 is admitted by the prototype but remains
untested in this qualification, which uses only width 32.

Memory admission counts three shared buffers, two host uploads and three
readbacks, plus the fixed 64 MiB runtime/diagnostic allowance. At the largest
tiny case, shared buffers occupy 4,202 bytes and host uploads/readbacks occupy
6,342 bytes: maximum admission is `67,119,408` bytes. All persistent fixture
payloads and bounded diagnostic records fit the allowance. The engine's 6 GiB
ceiling is unchanged; shared physical allocations are counted once.

Every completed native output value is validated before it is compacted to
payload hash, count, maximum source error/gate fraction and exact-FP16 diagnostic.
The full native JSONL remains in ignored raw output, bound by SHA-256. The final
record contains all warmup/sample proof rows, immutable-input checks, guards,
source/gate hashes, copied build inputs, binary and raw identities. The ordinary
add/tail, invalid-shader and insufficient-budget checks still run to qualify
the shared-owner/device-preparation refactor. Build output remains pinned inside
the fresh locked offline utility package.
