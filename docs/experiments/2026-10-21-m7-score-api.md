# M7 committed-distribution score API

An additive C diagnostic exposes one target's negative log likelihood without
copying a full vocabulary across the native boundary. This enables a later
phone teacher-forced quality collector. Numerical kernels, generation behavior,
precision choices, defaults and quality gates are unchanged.

The48-byte native-aligned `TokletScore` contains six32-bit counts/IDs and three
64-bit floating outputs. Target and greedy logits widen the resident FP32 values
exactly. The loss uses a max-shifted exponential sum with FP64 compensation and
subtracts target from maximum before adding log(sum), preserving meaningful
loss for tied finite logits near `f32::MAX`. Existing greedy validation rejects
nonfinite distributions and keeps the lowest token ID on ties. Backend choice
occurs once before this cold diagnostic reduction. No new model, logits vector
or GPU computation is introduced.

Only the current final fully committed distribution is available. A caller
uses zero-output generation, scores the next target, then appends it; a single
multi-token prefill does not expose earlier rows. Pending/reset/invalid states
reject. Cancellation may retain an earlier committed prefix, so exact history
and evaluated counts remain the caller's responsibility. Owner-thread, busy,
poison, panic and pointer guards apply, with output untouched on failure. The
[native contract](../native-abi.md) and C header specify these rules.

Three new CPU tests cover independent tiny logits/loss, hand-computed and
extreme distributions, ties, shape/layout, target validation, read-only state,
precancelled valid-prefix behavior, pending/reset rejection, null/misaligned
outputs, wrong-thread/busy calls and poison. The explicit selected-model Metal
test compares returned FP32 values bit-for-bit with independent direct-session
logits and loss against a balanced FP64 reduction within1e-12. Both models are
checked before and after a teacher-forced append, then reset for the original
three-token oracle and7/6/1 history/evaluated/pending checks.
