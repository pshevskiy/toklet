# Bounded native state witnesses — 21 October 2026

The harness adds an explicit sealed `--state` diagnostic for fully cached prompts,
append with a pending sampled token, changed-prefix reuse, cancellation during
prefill, and fully committed capacity rejection. It retains one immutable model
and one numerical session at a time. Exact cold saved-prefix copies are opt-in;
no numerical kernel, ABI, dtype, quality gate or default backend changes.

A canonical 12-field job reuses consumed-byte artifact/vocabulary admission.
Each command records bounded exact history, committed/pending counts, emitted
IDs/callback count, scalar score where requested, completed monotonic time,
physical footprint and foreground environment. Unexpected scene/warning events
use the existing cleanup handlers and fail the functional diagnostic. Independent
artifact endpoint proof runs even after a budget failure. Close/release must
complete before model artifacts are rechecked.

The cached prompt keeps an identical scalar target/greedy-logit/NLL diagnostic;
this is not full-distribution equality. A three-ID pending prefix plus two appended
IDs is compared to fresh evaluation of the exact whole prefix. A changed first
prompt ID is distinct and in vocabulary; three emitted IDs must equal an
independent reset/evaluation of that exact changed prompt.

For the physical-sized workload, the coordinator submits a 512-token prompt,
waits 50 ms as a trigger, then requests cancellation only while generation is
still busy and has emitted nothing. Success requires the completed native report
to show reason 3, zero callbacks, and strictly between zero and 512 committed
positions. The original whole prompt and its unevaluated input tail remain exact;
that tail can exceed one pending token. Continuing zero outputs must commit the
whole prompt, then three outputs must match a fresh original-prompt reference.
Tiny component checks explicitly skip this timing witness and report it false.

The boundary workload constructs exactly the admitted capacity (32 for tiny,
1,152 for the real model), commits every position with no pending tail, and rejects
continue-one, append-one and replacement-capacity-plus-one requests. Every rejected
operation must preserve exact history/counts, emit zero callbacks and leave an
identical scalar score taken immediately before and after it. INVALID state-query
reports correctly use reason zero. A subsequent reset/fresh changed prompt proves
continued usability. No mobile capacity is inferred from these Mac checks.

The successful-close publisher previously retained a prior operation status and
last numerical admission, and could retain emitted IDs after resources were gone.
It now clears status/message/admission/IDs/timings after successful native unload
and cancel-flag release. Release errors retain failure status. Direct error-to-close
and generated-output-to-close witnesses require acknowledged zero resource state;
earlier failure evidence remains in completed rows.

Astra source findings are fixed: exact invalid-operation semantics, close-state
publication, producer-width integer validation, and Boolean/float wrapper statuses.
Fifteen focused mutation tests and 206 portable methods across 21 isolated modules
pass. The final validator replays the existing v4 raw outputs byte-for-byte; only
the validator/error-wrapper checks changed afterward, and the exact executed two
helper snapshots remain pinned separately. All current Swift/app sources match
the v4 execution and both unsigned iOS builds. All 59 owned native/build commands
pass, including nested lifecycle/prefix/task/quality/measurement regressions.

Tiny CPU and Metal each record 26 command rows without claiming partial-prefill
qualification. The actual small-model Mac Metal run records 33 rows, proves partial
prefill, exact resumed/fresh outputs and a fully committed 1,152-position boundary.
Its peak observed physical footprint is 1,100,842,280 bytes. These checks are
correctness witnesses, not controlled performance or energy measurements.
