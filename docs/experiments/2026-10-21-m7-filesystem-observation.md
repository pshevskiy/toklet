# M7 read-only filesystem availability

The measurement runner now reads filesystem free bytes before artifact proof,
model loading or request timing. This prepares independent storage admission for
multi-GiB phone transfers. Astra cleared the source,45 portable checks and16
actual Mac CPU/Metal cases pass, and both strict SDK Release builds pass. The
updated signed app passes an actual physical tiny CPU run on iPhone14Pro
(`iPhone15,2`, iOS27.0.1). Astra accepted source and evidence; M7.3 is open.

`NativeFilesystemAvailability` reads the supplied trusted root's filesystem with
`FileManager.attributesOfFileSystem(...)[.systemFreeSize]`. The app supplies its
Documents root. The report includes the instrument and scope, free bytes, and
monotonic timestamps bracketing the read. This is reported filesystem space,
not guaranteed usable allocation capacity, an app quota, purgeable capacity or a
memory budget. No file is allocated or deleted to probe capacity.

The Foundation number bridge rejects Boolean, negative, zero, fractional,
nonfinite, overflow and nonnumeric values. Positive UInt64 conversion must retain
the exact integer; UInt64.max is explicitly checked. A missing filesystem root
throws. Observation errors preserve partial failed results and prevent loading.
The successful host checker requires the exact five-field object, positive
unsigned bytes/start timestamp, an ordered read window completed before the
first request, and the exact instrument/scope. Thirteen wire mutations cover
missing/extra fields, sizes, types, scope and timing. Existing timing/state/
foreground/identity/cleanup rules remain.

The physical first attempt was denied by iOS Locked, ran no inference and had
clean endpoint/process-absence checks. Its failure remains retained. The second
attempt passes three warmups and ten measured requests with exact `[47,47]`,
history6/committed5/pending1, matching model and seven signed-file proofs, strict
foreground conditions, close/weak-owner release and two clean process-absence
checks. The read reports **32,768,000,000 bytes** (about30.52GiB), bracketed by
device monotonic times132654962792250–132654962885875ns before all requests.
This value belongs to that observation only; Mac free space cannot substitute
for it. No real-model transfer or storage-reserve admission occurs in this task.

The [qualification receipt](../../benchmarks/results/2026-10-21-m7-filesystem-observation-qualification-v1.json)
binds current source/runtime inputs, private evidence hashes, the previous
accepted task and38 exact safe copies. Raw signing/device inventories stay
private. Cargo/numerical kernels, model limits, performance and energy are
unchanged and unqualified by this observation.

The next task must bind a successful observation to the same physical device,
current installation and exact transfer inventory. Freshness must use a
conservative host launch/start bound, checked immediately before transfer;
receipt completion is insufficient because the read precedes the run. Checked
source-byte totals plus an explicit reserve are required. This still cannot
guarantee that other filesystem users will not consume space afterwards.

Astra accepted code and publication after verifying261 bound paths,38 exact
published/staged copies, the independent phone replay, privacy, links and staged
whitespace. Review ran offline with no concurrent phone/native workload.
