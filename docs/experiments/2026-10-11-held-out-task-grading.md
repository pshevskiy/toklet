# Held-out task grading integration, 11 October 2026

The [grader](../../tools/bench/held_out_task_grading.py) connects a completed
100-response collection to the qualified literal Linux controller and protected
text scorers. The [window](../../tools/bench/held_out_task_window.py) admits the
stopped runtime, owns startup and restoration, and forbids grading before
collection processes exit. This is checked integration code. No held-out program
has been executed and no task score, candidate comparison or milestone acceptance
is claimed by this task.

Collection admission verifies the frozen 100-case order and requests, clean
recorded revision, qualified CLI and compiled sources, all thirteen helper
identities, model/contract/assets, exact readiness and execution policy, positive
bounded physical charges, complete response replay and native journal hashes.
Immediate hidden EOS and output-limit reset text remain valid under the protected
task semantics. The completed scalar collection passes this validation without
generating another response or scoring a case.

For each of the forty code cases, the grader uses the existing literal program
composition: source prefix, exact finalized completion, source tests and
`check(entry_point)`. It does not strip fences, repair indentation, add signatures
or alter tests. The program travels only through serialized bounded stdin to
the trusted bootstrap and qualified controller. Original dataset programs stay
in the ignored payload; published receipts retain binding hashes and raw results.
The controller source, image and fixed execution limits are unchanged from the
[28-case native qualification](2026-10-11-linux-literal-controller.md).

The thirty prose outcomes compare the whole trimmed response with the expected
uppercase letter. The thirty continuation outcomes compare the first whitespace
word with the exact expected word, preserving case and punctuation. All 100
resolved binary outcomes are required for the equal-weight aggregate.
An independently established resource limit remains a resolved failed outcome.
Compatibility, protocol or ambiguous runtime evidence remains unresolved with
`passed: null`; it prohibits the aggregate. A fully cleaned unresolved case can
be retained while later cases are attempted. Uncertain container/control cleanup
stops further container creation and retains the partial failure evidence.

The runtime window first checks the completed collection idle proof, its hash,
three distinct owned PIDs and empty process groups, the original held
orchestration, protected endpoints and the qualified literal controller sources.
It validates the complete collection before VM startup. The admitted stopped
machine/API connection and cached pinned arm64 image are checked without pulling
an image. Persistent startup helper pipes remain owned until verified shutdown.
Before stopping an owned VM, a healthy API inventory or fixed machine-SSH
fallback must show no running containers. Unexplained live containers or unknown
inventory retain the VM. Outer recovery preserves helper ownership even when
publication fails. Completing a runtime attempt does not imply that all quality
outcomes were resolved; that state and unresolved IDs remain explicit.

The [six grading checks](../../tools/bench/test_held_out_task_grading.py) cover
literal programs for all forty code cases, all 100 equal-weight outcomes,
unresolved compatibility, known resource failures, uncertain cleanup and
collection provenance mutations. The
[fifteen window checks](../../tools/bench/test_held_out_task_window.py) cover
PID/hash/provenance admission before startup, healthy and failed inventories,
the SSH fallback, pre-existing VM ownership, unexplained containers, stop/finish
sequencing and unresolved quality state. They mock all model, process and VM
boundaries and execute no generated program. The first targeted run exposed a
macOS `/var` versus `/private/var` temporary-path alias in fixture setup. Resolving
fixture roots fixes the setup; production paths and runtime policy are unchanged.
The first executed fixture source remains in ignored artifacts.
