# Resident fused Q4 execution

The Q4 execution code task is complete; M5.2 quality qualification remains open.
The [format/execution contract](../q4-v1.md) documents packed ownership, layouts,
the loading boundary and FP32 reconstruction/accumulation followed by checked
Half storage. CPU remains the default and the existing FP16 path is preserved.

## Mechanism

The immutable model holds seven packed matrices per layer and Half norms, QKV
biases and a single tied embedding/output allocation. Shared resources stay
resident. One SIMD group, whose width is queried from its pipeline, handles one
output row; adjacent lanes read adjacent input columns. Weights reconstruct in
registers, without a full-model or per-token expanded weight allocation. The
ordinary chunk still encodes all dependent operations in one command and waits
once. Failure/status/committed-prefix publication follows the existing backend.

All source hashes, tensor shape/format checks and packed/Half/staging admission
precede numerical use. After packed provenance is established, old planning
descriptors are dropped and exclusions load through newly validated descriptors.
An ordinary CPU regression verifies atomic replacement of the source file in
that interval, with old/new embeddings 1/2. Source identities are also checked
after loading. This source rebinding was an Astra review finding.

## Correctness evidence

On Apple M1 Pro, macOS 26.6.2, AC power, precise MSL 2.3 release builds:

- A direct GPU kernel test matches the manual 65-column affine oracle exactly,
  including bias, constant/tail rows, untouched output padding and subnormals.
  Finite FP32 results beyond Half range set the status error.
- The independent scalar NumPy Q4 tiny reference froze 175 arrays before GPU
  execution. Every stage is checked at full/3/1 chunks for five cases, including
  all 32 capacity positions and offset 5: 2,310 stage comparisons. Each chunk
  requires all 35 unique stages, exact dimensions/value counts, and frozen gates.
  Source/oracle/manifest identities are pinned, and CPU regeneration reproduces
  every fixture byte without a GPU or downloaded model.
- All seven Qwen projections in layers 0, 1 and 23 (21 operations) match the Rust
  FP64 oracle over reconstructed FP32 weights. The check uses the standard FP32
  dot-product `gamma_(columns+2)` bound on absolute products plus Half storage
  rounding; this is an execution bound, not quantization-quality acceptance.
- Q4 sessions pass exact budget admission, cached/pending replay, invalid-ID
  nonmutation, changed-prefix reset/replay, hidden stop IDs, already-set
  cancellation, output failure, and zero Rust allocations over 20 warmed steps.
  Native framework allocations are outside that counter.
- Complete Qwen forward execution generates eight tokens with 11 committed
  positions and one pending sample: `4460,311,1281,264,4285,2025,429,686`.
  This is execution smoke, without a held-out quality or speed claim.
- Existing FP16 tiny, capacity/Qwen intermediate and failure/replay GPU suites
  pass unchanged, including 612 frozen Qwen stage comparisons.

Tiny resident weights are 38,504 bytes; Qwen resident weights are 476,307,372
bytes (FP16 exclusions counted once). The four-prompt/eight-output Qwen smoke
session admits 547,978,160 numerical/metadata bytes; application allowance is
additional. The existing FP16 Qwen weight payload is 988,069,596 bytes. These are
physical buffer allocation counts, not a measured complete native footprint.
Steady native allocation/footprint and controlled timing qualify separately.

## Verification and scope

Default checks pass 83 tests; Metal-feature ordinary checks pass 89. Formatting
and strict all-target Clippy pass in both modes. Python: 15 quantization/artifact,
two exact-oracle tests and 137 experiment tests pass. Device/model suites run
explicitly and sequentially after isolated builds, with no overlapping benchmark,
build or large-file hashing process. Root CPU release executables are unchanged.
The [qualification record](../../benchmarks/results/2026-10-13-q4-decode.json)
binds final source, frozen fixtures, packed manifests, GPU binaries and logs.

Astra reviewed the code, source rebinding, exact stage coverage and allocation
test. Initial session harness runs incorrectly expected a valid changed prompt
to be rejected and then changed it before checking the older prefix. Correcting
those test expectations preserved engine behavior and all numerical gates;
failed logs remain under ignored `artifacts/`.

This accepts resident Q4 execution as an opt-in library capability. M5.2 still
requires the frozen 10,000-target loss and 100-case task comparison against the
unquantized checkpoint. Tiled prefill, measured fusion/greedy experiments, longest
prefix reuse, sustained/performance release and a larger checkpoint remain
M5.3–M5.6. No quality threshold or CPU-default decision has changed.
