# M6 longer-context release decision, 19 October 2026

M6 is complete for the selected Apple M1 Pro configurations. Retain explicit
Online attention with FP16 KV for the tested 4K, 8K, 16K and 32K total-token
cases. Both models pass the unchanged full loss/task gates, complete context
state/memory checks and actual maximum-context application generation. This
decision joins the accepted component evidence and records final FP16 retention.

The small model uses Qwen2.5-0.5B-Instruct compensated Half projections and
Original normalization. The larger uses Qwen2.5-1.5B-Instruct frozen group8 Q4 v2
compensated tiled projections and Compensated normalization. Both use FP16 KV,
FullLogits and chunk 128 on Apple M1 Pro, MacBookPro18,3, 16 GiB,
macOS 26.6.2 (25G83), optimized Rust 1.90.0 builds. Exact model, tokenizer,
packed format, contracts, executable and compiled-source identities remain in
the linked immutable receipts. No new numerical engine change accompanies this
final synthesis.

CPU scalar, GPU Original projection/Reference attention, FullLogits, chunk 128
and capacity 2,048 remain defaults. CPU admission remains capped at 2,048.
M7 and physical iPhone qualification remain pending.

## Numerical and quality evidence

The [Online component](2026-10-15-m6-online-attention.md) passes 81 adversarial
primitive cases, 173,184 tiny-stage values, independent references and session
state checks with zero warmed Rust allocations. Separate prefill/decode paths
avoid a full attention-score matrix and preserve causal masking, absolute
positions, GQA sharing and irregular chunks. [Long admission](2026-10-15-m6-long-admission.md)
adds structural, high-position rotary, tiny and CLI checks through 32,768.

The original 10,000 held-out targets and 100 equal-weight tasks remain frozen.
Both selected Online configurations satisfy loss increase at most 0.05
nats/token and task drop at most two percentage points against matched FP32.

## Completed context and application coverage

The [context qualification](2026-10-19-m6-context.md) covers all 32 roles:
two models, four depths, and quality/profile/ordinary/independent-confirmation
plans. Exact root and Astra replay matches across 22,752 raw events and 429
bindings. Each ordinary run has one warmup and two measured pairs; each fresh
confirmation has one measured pair. Three profile samples per mode measure
completed GPU attention fractions. Both modes finish full-capacity
recomputation and state-preserving overflow checks. All workers exit naturally
with clean cleanup/endpoints and unchanged input/source identities.

At 32,768 total tokens, 32,640 positions hold the prompt and 128 are reserved
for output. The frozen cyclic held-out stress sequence qualifies numerical,
state and capacity behavior. Natural long-document ability is unqualified.
Long timing counts support descriptive medians, MAD and ranges, without tail
or new performance-ranking claims. Controlled/teacher-forced continuation is
distinct from ordinary application generation.

Both [maximum-context applications](2026-10-15-m6-full-application.md) use the
real tokenizer-owning Online CLI, 32,640 raw prompt IDs and 128 ordinary greedy
outputs with EOS disabled. Exact output IDs/finalized text, reset, independent
post-exit decode and clean exit pass. Final history has 32,768 tokens, 32,767
committed KV positions and one pending sampled token. Both cyclic inputs yield
the same 128 output IDs (546 UTF-8 bytes, 89 distinct IDs); this is state/memory
evidence, without a natural-language or application-latency claim. Input
tokenization is excluded by raw-ID input.

## Performance and final KV decision

The [short-workload comparison](2026-10-15-m6-short-performance.md) retains two
full eight-row matrices plus independent primary confirmations. At 512 prompt
and 128 controlled output tokens, complete numerical request median reductions
repeat at 76.26% / 76.24% small and 73.02% / 73.03% larger. Three warmups and ten
alternating measured pairs per primary collection establish useful reductions
beyond the unchanged 5% threshold and observed variation. The frozen contract
named the workload without predeclaring a unique timing scalar; complete
request time is the reported primary metric, with all other metrics preserved.
Small prefill/TTFT ranges overlap, and the stricter all-metric range-separation
diagnostic stays false. These are numerical timings, excluding tokenization,
sampling and visible text. They do not establish an external-runtime lead,
application speedup or additive gain with M5's separate projection experiment.

Both maximum Online profile medians exceed the frozen 20% attention trigger:
97.2638% small and 95.6989% larger. This warranted the completed isolated
[I8 KV experiment](2026-10-15-m6-kv-component.md); completed-command attention
fractions do not establish a DRAM-traffic cause. I8 payload is 53.125% of FP16.
Small synthetic component gains of 5.0760% / 5.5617% are positive; larger
3.1995% / 2.6688% gains miss the frozen 5% usefulness threshold. The accepted
mixed-benefit decision declines optional production integration, without
inventing a requirement that all four runs pass or claiming end-to-end failure.

With complete FP16 context and actual application memory now qualified,
**retain FP16 KV and close the M6 KV evaluation**. No I8 engine was introduced.
I8 cache-write, full-model loss/tasks, long-state and end-to-end adoption gates
are neither passed nor waived; they remain required before any future adoption.
The component format/experiment stays reproducible. Existing Q4 v1 and small
Q4 v2 quality rejections, removed fusion experiments and M5 baseline limits
remain in the [improvement record](../improvements.md).

## Use and closure

After preparing the pinned local artifacts, build with Metal and select Online
explicitly. For example, with a short prompt at an admitted maximum capacity:

```sh
cargo build --locked --offline --release --features metal
target/release/toklet \
  --model models/Qwen2.5-0.5B-Instruct --backend metal \
  --metal-projection half-compensated --metal-attention online \
  --context-capacity 32768 --prefill-chunk 128 \
  --max-new-tokens 128 --prompt "Explain ownership in Rust." --json
```

For the larger selected artifact use `--model models/Qwen2.5-1.5B-Instruct`,
`--metal-projection q4-v2-compensated-tiled` and
`--q4-weights artifacts/m5-larger-q4-v2`. There is no automatic fallback.
Reserve requested outputs inside capacity; tested total-token cases are
4,096, 8,192, 16,384 and 32,768. Other hardware and mobile limits require
independent qualification.

The [final receipt](../../benchmarks/results/2026-10-19-m6-release-qualification-v1.json)
joins eleven accepted prerequisite receipts and the protected CPU binaries,
with a separate final FP16 retention decision. Older component/context receipts
retain their original KV/M6 false flags and pending-at-collection scope.
The completed queue is idle before offline checks. Fresh checks pass 105 Python
tests, formatting, strict all-target Metal Clippy, 97 CPU tests (8 ignored) and
110 Metal-feature tests (58 ignored), using an isolated Cargo target. Ignored
hardware/model tests are separate from the explicitly collected native evidence.
The initial publication helper v1 stopped before creating a receipt because
the older application receipt indexes replay pins by published path. Its source
is preserved; reviewed v2 accepts either exact key convention and rejects
missing/conflicting hashes. No numerical data or gate changed.
Final documentation changes use content/link/whitespace checks. Astra accepted the final
synthesis and publication after independently verifying all 497 bindings
(5,485,161,301 bytes), eleven exact prerequisites, 421 local link targets,
status and reported scope. M6.1–M6.3 are complete in this qualified scope;
M7 remains outside this release.
