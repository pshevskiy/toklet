# Q4 v2 group 8 storage and oracle qualification

A separate group-8 Q4 candidate now has a source-bound packer, validated Rust
matrix/model inventory and independent scalar reconstruction oracle. V1 remains
the default packer format, and its exact fixtures, artifacts and quality rejection
remain unchanged. V2 GPU execution is rejected before compilation or allocation
until the next numerical task implements and qualifies its kernels.

The [frozen candidate contract](../q4-v2.md) specifies distinct matrix/model and
quantizer identities, eight codes plus two Half metadata values per group,
canonical tails/padding and unchanged source/rounding/overflow/exclusion rules.
It freezes existing compensated vector/tile projection and normalization
mechanisms before new quality evaluation. The layout uses one byte per weight
including metadata before alignment, rather than claiming four-bit total storage.
Predicted small/larger resident weights are630,251,436/1,777,247,428bytes; these
are independent layout calculations from existing shapes, not native admission.
No new held-out corpus, model response or quality score is produced by this task.

[Python packing](../../tools/quantization/q4v2.py) and the explicit
[model option](../../tools/quantization/model.py) preserve one-row conversion,
exact source/config/shard endpoints, exclusive destination ownership and cleanup
of owned incomplete outputs. [Rust parsing](../../src/q4.rs) allocates nothing,
accepts only matching magic/version/group triples and checks shape/overflow/length,
metadata and canonical storage before exposing borrowed weights. The matvec
oracle selects bounded static implementations once per operation, reconstructs
in FP32 and accumulates in FP64. A first validation pass preserves caller output
on nonfinite/overflow results; weights are not expanded.

[Artifact admission](../../src/q4/artifact.rs) calculates bytes from the validated
format and rehashes each exact staged matrix before parsing. Manifest/header
version mismatch fails even with matching shape, size and refreshed authentic
hash. Format identity is immutable through its public accessor. The existing
Metal loader refuses v2 before GPU creation, allocation or v1 kernel dispatch.

The [manual fixture](../../tests/fixtures/q4-v2/manifest.json) was assembled from
known scale/bias/nibbles independently of either packer. Both languages reproduce
its exact192bytes and all34reconstructed values. Additional hand-encoded Rust
records cover1/7/8/9/15/16/63/64/65columns, independent expected dots and bad tails.
Tests cover constants, signed zero, metadata ties, subnormals, finite extremes,
malformed headers/padding, negative/nonfinite scale, size overflow, atomic output
preservation, existing destination protection, changed sources and version mixing.

Twenty quantization Python checks pass, including all unchanged v1 checks and
five new v2 tests. Full ordinary CPU tests and the Metal-feature suite pass;
the latter records101passes and45explicit ignores before the final added
boundary-only test. The final targeted q4/q4_artifact/q4_v2 suites pass11tests.
Formatting and Metal-feature all-target Clippy with warnings denied pass on the
final files. Cargo uses only `artifacts/m5-checks`; protected release CPU binaries
are unchanged. Explicit real-model/GPU tests remain separate from these storage
checks. [Receipt](../../benchmarks/results/2026-10-14-q4-v2-format-qualification-v1.json)
binds sources, independent fixture and check logs. No timed native workload or
new model packing overlaps the checks.

Astra accepted the prior design, code, independent boundary test, check logs,
bindings, layout predictions and links with no remaining findings. This is a storage prerequisite,
not M5.2/M5.6 completion. Next qualify new independent reconstructed-graph
fixtures and GPU vector/tile/state/memory behavior, then apply the unchanged
short/full quality suite and performance acceptance. A candidate quality failure
stays rejected; no iterative held-out grouping/metadata search is authorized here.
