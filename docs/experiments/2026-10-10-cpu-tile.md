# Ordered FP64 projection tile candidate, 10 October 2026

The [scalar profile](../../benchmarks/results/2026-10-10-cpu-short.md) places
99.24% of sampled stacks in projections. Its hot dot product has one serial
FP64 accumulator. Hypothesis: updating independent output cells together and
reusing inputs/weights will reduce latency without changing numerical order.
The declared engine primary metric will be warm 128-input/128-output TTFT;
retain only after full workload correctness, memory, and timing checks, a
second confirming run, and the plan's improvement threshold.

The [candidate](../../src/cpu/tiled.rs) consumes row-major input
`[tokens, in_features]`, weights `[out_features, in_features]`, and output
`[tokens, out_features]`. Four token rows and four output rows share a feature
loop with sixteen independent FP64 accumulators. Each cell visits features in
increasing order, adds optional bias after the dot, then rounds once to FP32.
One-row token tails and scalar output tails cover arbitrary nonzero shapes.
The existing scalar implementation and default decoder are unchanged.

No packing, allocation, unsafe access, CPU intrinsics, forced inlining,
reassociation, extra alignment, or threading is introduced. Specialization is
bounded to four rows and one row. The largest accumulator array is 128 bytes;
this is not a measurement of the complete compiler stack frame. Per tile, each
feature loads four weights and four inputs and performs sixteen FP64 products
and additions; these are source-level accesses, not measured DRAM traffic.
Both kernels retain complete input/weight finite scans in the operation timer.

Optimized arm64 inspection of candidate binary
`cbf6d2a9b5340e9536ea87df12a9916fe943ce6ce620a4dcc6709dcbc7f52d88`
shows the four-row feature loop at `0x1000069a0..0x100006a70`: eight FP32
loads/conversions feed sixteen separate scalar FP64 multiply/add updates.
The compiler preserves each sum's order and keeps independent sums in registers.
These instructions support the scheduling/reuse hypothesis; they do not prove
which hardware resource limits the full decoder.

## Paired synthetic measurements

[Run 3](../../benchmarks/results/2026-10-10-projection-pairs-3.json) and
[run 4](../../benchmarks/results/2026-10-10-projection-pairs-4.json) are complete
records on Apple M1 Pro, MacBookPro18,3, 16 GiB, macOS 26.6.2 (25G83), Rust 1.90.0,
ordinary optimized Cargo release flags. AC power was attached, AC low-power
mode was disabled, and no thermal/performance warning was recorded at the start
or end of either run. Both started from revision `337515e` with this uncommitted
candidate; exact source, binary, input, weight, and output hashes are retained.

Each representative Qwen projection shape uses deterministic synthetic FP32
weights, three warmup pairs, and ten measured pairs. Pair order alternates,
five scalar-first and five candidate-first. Timing covers the complete checked
operation with no bias. Allocation, data hashing, bit comparisons, transport,
and memory inspection are outside timing. Every warmup and measured pair is
bitwise equal. The nine synthetic shapes are not trained-model quality checks.

The baseline model was resident in a separate stopped process during these

performance jobs stopped. That paused warmup is not performance evidence.

## Correctness and decision

[Tests](../../tests/cpu_tiled.rs) cover all frozen tiny-layer projections and
output projection against exact scalar bits, independent unchanged numerical
tolerances, every tile-tail combination, manual outputs, cancellation-sensitive
ordered sums, signed zeros/subnormals/range extremes, pre-write input rejection,
and global output error indices. Formatting, Clippy with warnings denied,
74 ordinary Rust tests, release candidate build, 18 offline Python checks,
byte-exact raw checkpoint copies, source/binary/data identities, and summaries
pass. Explicit real-model suites were not rerun because the decoder is unchanged.
Astra accepted the completed code task without findings and independently
verified both final records, checkpoint rows, source/binary/data identities,
summaries, power policy, and the candidate-only scope.

Decision: carry this promising candidate into separately reviewed engine
qualification. The later [opt-in functional check](2026-10-10-cpu-tiled-engine.md)
prepares full-workload measurement while the scalar matrix continues. It is not
selected by default for ordinary inference, and M3.1 remains open. No full-model speed,
held-out quality, or end-to-end retain decision follows from these microbenchmarks.

```sh
cargo build --locked --offline --release --example cpu_projection_bench
.venv/bin/python tools/bench/projection.py --output benchmarks/raw/projection-first.json
.venv/bin/python tools/bench/projection.py --output benchmarks/raw/projection-confirm.json
```

Run performance jobs sequentially. The driver checkpoints each completed shape,
refuses existing final/raw paths, reads process memory only while the worker
waits between shapes, and terminates/reaps its own worker on failures. A one-hour
watchdog bounds unexpected hangs. Partial rows survive as incomplete evidence;
they are not silently resumed or overwritten.
