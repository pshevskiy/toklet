# M6 Online attention quality collector

15 October2026. This code task qualifies the collector and short real-model
guards. It does not establish full loss/task quality, latency, long contexts or
M6 completion.

The release loss worker accepts an optional trailing `online` argument. It
constructs the actual Online session before admission and reports Online in
readiness. Without that argument, execution and the legacy readiness schema stay
unchanged. All-required-row scoring, independent1025-token blocks, stable FP64
loss math,128-row chunks, handshakes and completion/state checks are unchanged.

The M6 collector admits only selected small compensated Half or larger frozen
Q4 v2. It binds complete compiled-source closure, immutable snapshot, executable,
source checkpoint/config, corpus, unchanged FP32 baseline, packed payload
inventory and exact short-probe source bytes. It reasserts build/source identity
immediately before each owned worker is launched. Manifest reads are bounded to
1MiB+1 from one descriptor, both initially and on recheck. Actual worker readiness
must select Online and the expected representation/geometry/admission.

Both frozen short probes run at chunk1 and128 before the optional full10000-target
run. The existing1e-3 single/batch NLL envelope and0.05-nat full mean-NLL gate are
unchanged. A probe-only collection cannot claim full quality; a completed full
loss rejection retains completed flags and a failed gate. Post-exit identity,
ordered raw events, natural exit/cleanup and owned native memory remain required.

binds code, compiled build, snapshots, checks and short native evidence.

guard-before-full ordering, early failure and unchanged completed rejection.
