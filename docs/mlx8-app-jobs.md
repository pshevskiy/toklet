[Staging](../tools/experiments/m8_mlx_jobs.py) retains exact legacy tiny/four-bit recipes. [Physical admission](../tools/experiments/m8_physical_mlx.py) applies fresh same-app storage proof and replayed ready-receipt admission to every admitted non-tiny candidate. Only tiny can bypass the real-model storage proof. Regressions cover both public candidates' missing-proof rejection and ready-proof replay, exact eight-bit identities and parity of every full workload contract. All 101 portable methods pass in seven owned commands.

The existing pinned Mac app runner and signed installed iPhone app already contain the native eight-bit kernels, so this task changes no Rust, Metal, Swift, ABI, package or signed bundle. The trial admits the exact compiled source/header/package closure and binary identity while binding the current host helpers separately. It does not pretend old Python validator bytes are current.

Mac trials use the existing app coordinators for short generation, scoring, task responses and all component state rows. Phone trials use a fresh tiny transfer, three fresh same-device tiny storage observations, three authenticated eight-bit transfers and three no-copy collection launches. These cover 13 four-token requests, three corpus scores and one original task with an eight-token short cap on each device. They do not qualify the full 10,000-target loss gate or 100-task quality suite.

All four Mac jobs and ten phone stages pass, with 14 clean owned outer commands and 104 clean transport commands: 94 `devicectl` operations and ten host boot queries. Twenty verified absence endpoints comprise 19 natural absences and one identity-checked initial preflight reset of the already installed app; that reset finishes before copying or inference. Six phone console replays match their recorded checks exactly. There are no endpoint or cleanup errors.

These are selected short-workload physical peaks under explicit trial budgets; no representative throughput, sustained behavior or general mobile fit follows.
