# Matched FP32 MLX short baseline, 10 October 2026

[Raw samples](2026-10-10-mlx-fp32-128-128.json) retain three warmups and ten
completed 128-input/128-output teacher-forced requests on Apple M1 Pro with
16 GiB, macOS 26.6.2 (25G83), AC power and no reported thermal warning.
The pinned BF16 checkpoint is converted to FP32 weights before warmup; all
parameters and actual KV dtype are checked. This matches Toklet's storage
representation. Numerical reduction implementations differ across engines;
no held-out quality or speed ranking is claimed.

| Measurement | Result |
| --- | ---: |
| Warm TTFT median | 60.260 ms |
| Warm TTFT min–max | 52.837–64.363 ms |
| Prefill median | 2126.73 tokens/s |
| Decode median | 68.967 steps/s |
| Complete request median | 1.902777 s |
| Model load including conversion | 1.708743 s |
| Nested completed conversion | 0.616795 s |
| Physical process peak | 3342387216 bytes |
| Logical weights | 1976131072 bytes |
| Allocated KV | 6291456 bytes |

Model conversion uses the pinned MLX module's floating-parameter dtype update,
then `mx.eval` of all parameters. Conversion allocations are cleared before
warmup; no second live model is retained by the adapter. Physical peak covers
loading/conversion, Python/tokenizer state and all requests, and fits 6 GiB.
Native KV grows in 256-token increments: 255 positions are committed and the
last fixed output token remains pending, with capacity 256 for this workload.
Admission remains 2,048; physical allocation differs from Toklet's fixed cache.

The same frozen prompt/continuation token hashes are used for the CPU short
workload. Token timestamps follow completed final logits and all layer states.
Prefill computes only KV for the first 127 input tokens, clears the allocator
cache, then computes the last token's distribution. Decode counts 127 intervals;
tokenization, sampling, detokenization and visible-text latency are excluded.
TTFT includes native cache/input-array setup; model load is separate. Hashing
warms the weight file, so load time is not a cold-storage measurement. Isolated
kernel compilation, scratch, memory-pressure state and energy are unavailable.

The concurrently resident CPU benchmark child was stopped during its first,
excluded warmup for this entire MLX run and resumed in a `finally` block. No
CPU benchmark computation ran during the MLX samples; its remaining warmups
and measured requests follow afterward. The first CPU warmup's elapsed time
therefore includes this diagnostic pause and is not a performance sample.

Reproduce on the prepared pinned environment with other performance jobs stopped:

```sh
.venv/bin/python tools/bench/mlx_baseline.py --dtype fp32 --prompt-length 128 --output benchmarks/raw/mlx-fp32-short-repeat.json
.venv/bin/python -m unittest discover -s tools/bench -p 'test_*.py'
```
