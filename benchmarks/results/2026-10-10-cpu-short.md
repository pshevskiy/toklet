# Scalar CPU short baseline, 10 October 2026

[Raw samples](2026-10-10-cpu-short.json) retain three warmups and ten completed
128-input/128-output teacher-forced requests on Apple M1 Pro, MacBookPro18,3,
16 GiB, macOS 26.6.2 (25G83), AC power with low-power mode disabled. Each request
resets its session. No thermal or performance warning was reported at either
end of the run. The ten measured requests take over 21 minutes in total; this
also records a sustained sequence of this one workload. Other contexts and the
coding/tool-result application transcript remain pending.

| Measurement | Result |

| Warm TTFT min–max | 39.967942–40.289741 s |

The record began from clean engine revision `996f8e7df0f3eb6a8957fe506e4feae94c200c67`.
Its runner SHA256 identifies that revision's `tools/bench/cpu.py`, rather than
the later external-comparator edits. The record also freezes the release binary
and common helper hashes. Immutable model weights, bounded session buffers and
completed synchronous final distributions are timed. Sampling, tokenization,
detokenization, JSON transport, admission and event-buffer allocation are outside
the request timer. The last fixed output token remains pending, so the measured
request commits 255 of its 256 history positions. KV capacity remains 2,048.

The first excluded warmup was paused while collecting the separate matched FP32
MLX baseline, then resumed; its elapsed time includes that pause. The remaining
two warmups and all ten measured requests ran with other performance jobs
stopped. Read-only source inspection and small tooling tests continued. The
five-second [native profile](2026-10-10-cpu-short.sample.txt) was collected during
that first excluded warmup. Of 3,686 samples, 3,658 are in `matmul_f64` (99.24%).
Inspection of the release arm64 instructions maps the hot offsets to conversion
and serial FP64 additions within the dot product. This selects projections as
the M3 optimization target; it does not establish an optimization result.

The physical footprint includes loading and request execution and stays below
6 GiB. Source hashing warms the file cache; loading is not cold-storage timing.
Memory pressure, energy and visible-text latency were not measured. The
[matched MLX record](2026-10-10-mlx-fp32-128-128.md) uses the same token IDs and
FP32 weight/KV storage, with different native allocation and reduction behavior.
No held-out quality or general speed ranking follows from these short records.

```sh
cargo build --locked --offline --release --example cpu_bench
.venv/bin/python tools/bench/cpu.py --workload short --output benchmarks/raw/cpu-short-repeat.json --profile benchmarks/raw/cpu-short-repeat.sample.txt
```

M2.5 remains open for the full workload matrix, independent llama.cpp comparison,
application trace and real-model capacity execution. This baseline changes no
numerical code and does not qualify later engine revisions automatically.
