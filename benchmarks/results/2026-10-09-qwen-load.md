The 64 MiB metadata allowance is an admission estimate. Physical peak comes
from the kernel's own-process `footprint` `auxiliary.phys_footprint_peak`, includes
test/hash setup, and is below the initial 6 GiB ceiling. No numerical execution,
KV, session scratch, tokenizer, or application state is included in this loader
check. These must be admitted and measured when implemented. The model is not
yet qualified against real-model forward values.

cache. This is one functional load check, with no warmups/repetition series or
cold-storage/performance claim. The implementation was checked at pre-task

Reproduce with explicitly prepared local weights:

```sh
.venv/bin/python tools/bench/prepare.py --fetch-weights
cargo test --locked --offline --release --test weights pinned_qwen_loads_within_the_initial_budget -- --ignored --nocapture
```

On macOS the explicit test requires own-process footprint access. Ordinary tests
use synthetic single/sharded artifacts and frozen tiny arrays, with no downloads
or Apple device dependency. They cover known half-precision bit patterns,
conversion chunk boundaries/tails, tied-head consistency, unsupported configs,
insufficient admission, missing/extra tensors, shapes/dtypes, nonfinite values,
shard mappings, truncated files, and duplicate metadata names.
